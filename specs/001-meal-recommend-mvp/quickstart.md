# Quickstart: 집밥 요리 추천 서비스 MVP

구현이 스펙을 만족하는지 빠르게 검증하는 가이드. 계약 상세는 [contracts/](./contracts/), 엔티티는 [data-model.md](./data-model.md) 참조.

## 사전 조건

- Node.js 22+ (기존 리포 툴체인)
- 의존성 설치: `npm install` (React·Vite는 tasks 단계에서 추가됨)

## 명령

| 목적 | 명령 | 기대 결과 |
|------|------|-----------|
| 타입 검사 | `npm run typecheck` | 오류 0 |
| 전체 테스트 | `npm test` | 단위 + 통합 전부 통과 |
| 개발 서버 | `npm run dev` | 로컬 URL 출력, 모바일 뷰포트로 접속 |
| 프로덕션 빌드 | `npm run build` | `dist/` 정적 산출물 (서버 불필요) |

## 검증 시나리오 (수동 스모크 — 개발 서버에서)

각 시나리오는 spec.md의 수용 기준과 1:1 대응. 자동화 버전은 `tests/integration/`에 존재해야 한다.

1. **온보딩 → 첫 추천 (US3)**: 저장소를 비운 상태로 접속 → 문항이 3개 이하인지, 응답 직후 첫 추천이 뜨는지, 못 먹는 재료로 등록한 것이 추천에 절대 안 나오는지.
2. **Zero-Question Home (US1)**: 홈에 추천 카드·근거 한 줄·"오늘 지쳤어요" 버튼 외 요소가 없는지. 새로고침해도 같은 추천이 유지되는지(하루 고정). "다른 메뉴 보기" 후에는 바뀐 추천이 유지되는지.
3. **재고 없이 추천 성립 (FR-005)**: 재고 데이터를 비워도 추천과 근거(제철·취향·가격)가 나오는지.
4. **레시피 상세 (US2)**: 1인분 현실 계량 표기(소수점 개수 없음), 원본 출처(채널명·영상 제목·링크), 시간·난이도·설거지 태그·재료비·영양 태그 표시.
5. **요리 완료 (US4)**: 완료 원탭 → 이력 기록·재고 차감. 완료 후 화면에서만 확인형 질문("~ 아직 있죠?")이 나오는지 — 홈에는 절대 없음.
6. **지침 모드 (US5)**: "오늘 지쳤어요" 원탭 → 15분·1구·설거지 최소 메뉴로 전환, 추가 질문 없음. 새로고침에도 유지. (자정 경과 해제는 통합 테스트로 검증)
7. **가격 표시 (US6)**: 레시피 상세에 "이번 장보기 ○○원 → 이걸로 N끼" + 끼당 환산가 + "평균 시세 기준 추정(기준 연월)" 문구. 홈에는 가격 노출 없음. 절약 화면에 (기준가 − 재료비) 누적.
8. **오프라인**: 개발자 도구에서 네트워크 차단 → 홈·레시피 열람 정상 (PWA).

## 자동 테스트가 반드시 커버해야 하는 것 (수동 확인 불가 항목)

- 자정 경계: 하루 고정 리셋, 지침 모드 자동 해제 (fake timer).
- 완화 순서: 필터 후 후보 0 → 7일→5일 등 단계 완화, 못 먹는 재료 불변식 유지.
- 첫 주 콜드스타트 풀 우선 → 8일째부터 일반 가중치.
- 수용 판정: 요리 완료 원탭만 SC-002 집계에 반영.
- 카탈로그 로더 검증: [catalog-schema.md](./contracts/catalog-schema.md)의 표 전체.
